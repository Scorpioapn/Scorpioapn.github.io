# Agenda Builder 产品设计审计

审计日期：2026-07-16

审计对象：https://scorpioapn.github.io/agenda_generator.html
范围：桌面端首次引导、完成引导后的编辑器、键盘焦点管理、200% 等效重排、reduced-motion、Android Chrome 模拟，以及 iPhone 尺寸与 Safari UA 的 Chromium 近似模拟。

## 总体判断

产品的基础质量已经很好：agenda 成品信息完整、品牌感明确；移动端的底部导航、议程列表和编辑抽屉尤其成熟；自动保存、实时预览、PDF/打印/文字版/JSON 都把真实工作考虑到了。

真正的问题不是“功能不够”或“缺少引导”，而是 builder 仍按功能区组织，而不是按每周开会前的任务组织。七步强制导览解释得很全，却弱化了最重要的动作：导入接龙或沿用模板、补充本期信息、微调议程、检查并导出。

建议保留 agenda 的全部内容与 A4 版式，把 builder 改成一个更安静的后台工作台，让 agenda 本身继续做视觉主角。

## 最高优先级建议

1. 用“本周从哪里开始？”取代七步强制导览。首屏只给三个入口：`导入接龙`（主按钮）、`沿用上期/更换模板`、`继续当前草稿`。下面常驻三步进度：`本期信息 → 调整议程 → 检查并导出`。
2. 按使用频率重组左栏：`每周必做`（信息、导入、议程）始终展开；`每周检查`（下期预告）半展开；`偶尔维护`（Logo、二维码）与`长期固定`（关于我们、团队、守则）默认收起。内容不删，只改变出现顺序。
3. 修复导览第 3 步和完成后的落点。第 3 步应把“添加项目/添加分组”和前两条议程同时带入视野；点击完成后应回到页面顶部或“导入接龙”，而不是停在左栏底部。
4. 桌面端保留左右分栏，但左栏顶部增加粘性步骤导航，右侧只保留一个粘性导出栏。当前 `保存 PDF / 打印 A4` 同时出现在预览顶部和导出卡片，层级重复。
5. 增强“点行编辑”的可见性。桌面端在行 hover 时显示 `编辑` 或铅笔；移动端在首条议程上做一次轻量提示，或让整行有更明显的按压状态。不要依赖只出现一次的说明文字。
6. 移动端 A4 预览增加 `点按放大` / `全屏预览`。现在缩略图适合判断是否一页，但不适合检查文字与错别字。

## 视觉方向

- 核心原则：编辑器安静，agenda 权威。保留 A4 成品的深蓝与酒红；builder 以暖白和深蓝为主，酒红仅留给成品预览。
- 将目前大量 20px 以上圆角收敛到 12–16px；阴影只用于浮层、编辑抽屉和粘性导航，普通卡片用 1px 细边框区分。
- 按钮只保留三个层级：深蓝主按钮、描边次按钮、无底色文字按钮。浅蓝不再同时用于大量同等级操作。
- 中文界面使用一套清晰的无衬线字体（如 Noto Sans SC / 思源黑体）；保持 14px 正文、16px 区块标题、24px 页面标题的稳定层级。
- 减少“卡片套卡片”。特别是桌面左栏，让分组标题、字段和列表直接形成节奏，避免每一层都用圆角容器和阴影。

## 流程健康度

1. 会议信息：良好。字段完整、自动保存明确；但首次导览遮挡了用户本来就能看懂的表单。
2. 导入接龙 / 更换模板：良好且应前置。这是每周最自然的起点，应成为首屏主任务。
3. 当前议程：需修复。导览将左栏滚到列表中段，“添加项目/添加分组”反而离开视野。
4. 图片与固定信息：良好，但属于低频维护，不应占用首次导览的核心步骤。
5. A4 实时预览：优秀。成品感强，是产品最有说服力的区域。
6. 导出与备份：基本良好。输出方式齐全；PDF/打印与 JSON 备份应分成“完成会议”和“数据管理”两个层级。
7. 多设备同步：有价值但可选。放入高级设置或首次需要时解释即可。
8. 完成引导：需修复。完成后停在左栏底部，用户无法立即开始主任务。
9. 移动端会议信息：优秀。字段、按钮尺寸和底部导航清晰。
10. 移动端议程列表：良好。扫描效率高；“点行编辑”的提示仍略弱。
11. 移动端项目编辑：视觉与触控良好，但可访问性需修复。编辑抽屉结构清楚，主按钮位置稳定；不过 Tab 焦点会逃到背景页面，关闭后焦点也没有回到原议程行。
12. 移动端 A4 预览：需增强。适合看整体，不适合检查细节。
13. 移动端导出：良好。操作很明确，但应把 JSON 备份视觉降级为次要工具。

## 可访问性

移动端 Lighthouse 截图态检查得分 94/100，未发现明显颜色对比失败。页面的主区、编辑区、对话框、按钮和输入框大多具有可读名称。

已确认的问题：`导入 JSON` 对应的隐藏文件输入缺少关联 label，而且视觉隐藏后仍可能成为无名称的 Tab 停靠点。建议为 `#jsonImportInput` 添加 `aria-label="导入 JSON 文件"`，并在保留可见按钮为唯一入口时设置 `tabindex="-1"`，或改为显式关联的 label 方案。

补充实测结果：

1. 新手引导弹窗：通过。可访问性树将其识别为有名称、有说明的模态 dialog；Tab 与 Shift+Tab 会在“下一步/完成”间循环，Esc 关闭后焦点返回“重新查看引导”。
2. 移动议程编辑器：失败。虽然运行时具有 `role="dialog"`、`aria-modal="true"` 和标题关联，但 Tab 从“保存修改”继续后会进入遮罩与背景页面；Esc 关闭后焦点落到 `body`，没有回到触发它的议程行。
3. 状态播报语义：基本通过。同步冲突、打印溢出、接龙预览与 Toast 共四处具有 `aria-live`/`role="status"`。浏览器可访问性树能确认语义，但本次会话未提供 Windows 电脑控制连接器，因此没有启动 Narrator/NVDA；实际朗读文案、时序与重复播报仍未验证。
4. 200% 缩放：部分通过。浏览器页内快捷键无法修改 Chrome 的浏览器级缩放，因此采用 1440×1000 的 200% 等效 CSS 视口（720×500、DPR 2）验证重排。页面转为单栏、文字可读、没有横向页面溢出；标题会换为两行。真实 Chrome 200% 菜单缩放仍建议补一次人工确认。
5. Reduced motion：失败。线上 CSS/JS 没有任何 `prefers-reduced-motion` 分支，但 spotlight、菜单、按钮、议程行和上传浮层存在 160–180ms transition。系统“减少动态效果”偏好不会改变这些动效。

## 移动平台补测

1. Android Chrome（Pixel 7 模拟，412×915、DPR 2.625、触控、Android UA）：通过核心视觉与交互检查。信息、议程、编辑抽屉和 A4 预览均无横向页面溢出；固定底部导航距视口底部 6px；编辑抽屉的取消/保存按钮保持可见，未被导航遮挡。
2. iPhone 近似模拟（393×852、DPR 3、触控、iOS Safari UA）：通过 Chromium 下的响应式检查。四个核心状态无横向页面溢出，A4 缩略图完整适配宽度，编辑动作区未被遮挡。样式中使用了 `safe-area-inset-*`，但页面 viewport 未声明 `viewport-fit=cover`。
3. 这不是一台真实 iPhone，也不是 WebKit。改变 UA 不会把 Chromium 变成 Safari，因此不能据此确认真实 iOS Safari 的输入控件、键盘抬起、safe-area 非零值和打印行为。

## 证据限制

本审计基于 1440×1000 桌面视口、720×500/DPR 2 的 200% 等效重排、412×915 Android Chrome 模拟、393×852 iPhone 外形与 Safari UA 的 Chromium 近似模拟、当前真实数据以及页面可访问性树。没有执行 PDF 文件内容比对、真实打印机输出、Narrator/NVDA/VoiceOver 完整操作、真实 Safari/WebKit 或多人同步冲突测试。
