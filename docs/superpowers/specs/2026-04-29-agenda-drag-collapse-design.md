# 议程拖拽排序与轻度折叠设计

## 目标

让会前设置页在准备议程时更高效：新增议程拖拽换顺序，并把低频内容折叠起来，同时不改变计时逻辑和日常会议工作流。

## 已确认方向

按 `D:/Codex/usechrome/agenda_simplify_demo.html` 的视觉方向实现：议程设置保持核心位置，议程行增加拖拽手柄，低频设置区改为可折叠。

## 议程排序

- 在每一行议程最左侧增加一个小拖拽手柄。
- 只允许拖动“未开始”的议程环节。
- “进行中”和“已完成”的议程环节锁定，避免误改历史顺序和计时记录。
- 拖拽排序完成后，根据例会开始时间和每个环节计划时长，重新计算计划时段。
- 排序后走现有 `saveAgenda()` 保存路径，写入本地存储。
- 排序后重新生成报告，确保报告顺序和议程表一致。
- 保持现有“开始”“结束”“删除”行为不变。
- 在触摸屏或移动端，给未开始议程提供“上移 / 下移”按钮，避免手机拖拽不稳定。

## 折叠行为

- `例会总控` 和 `议程环节` 默认保持展开，因为它们是会前准备的主流程。
- `会议信息` 改为可折叠，默认展开。
- `时间官介绍` 改为可折叠，默认收起。
- `时间规则设置` 改为可折叠，默认收起。
- 每个折叠状态保存到 `localStorage`，下次打开沿用用户上次状态。
- 折叠标题仍显示必要上下文：
  - `会议信息`：显示会议名称和日期。
  - `时间官介绍`：说明这是给听众看的介绍页。
  - `时间规则设置`：显示当前规则数量。

## 视觉要求

- 保留当前暖色 Toastmasters 风格和整体布局。
- 不引入新的颜色体系。
- 议程表外观保持熟悉；拖拽手柄要低调，不抢“开始 / 删除”按钮的注意力。
- 高频操作不隐藏到折叠区里。
- 移动端仍保持可用：表格可以横向滚动，并提供明确的上移 / 下移排序按钮。

## 技术边界

- 主要修改单页应用 `index.html`；如需临时验证脚本，可放在仓库外。
- 不引入第三方拖拽库。
- 使用原生浏览器事件，并复用现有 `agendaItems`、`saveAgenda()`、`renderAgenda()`、`generateReport()` 流程。
- 不改变计时器状态逻辑、默认时间规则映射、报告格式、记录删除、舞台模式行为。
- 已修复的代码审查点必须保留：
  - 1 秒定时器内不重绘整张议程表。
  - 不重新引入 inline `onclick`。
  - 现有 label 绑定保持有效。
  - 全屏状态同步监听保持有效。

## 验收标准

- 桌面端可以拖动未开始议程行排序。
- 进行中和已完成的议程行不能拖动。
- 移动端可以用上移 / 下移按钮调整未开始议程。
- 排序后会更新行号、计划时段、本地存储、现场页下一议程、会后报告。
- 折叠区域打开/关闭时不丢失输入内容。
- 折叠状态刷新页面后仍能保留。
- JavaScript 语法检查通过。
- 现有议程默认时间规则验证仍通过。
